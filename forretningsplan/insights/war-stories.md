Key learnings fra privat projekt:
-Jeg har opsat forskellige parser på min app på en seperate side for test.  fordi så behøver man ikke vente på embedding ind til vektordatabasen. Så hvis man alligevel skal kunne konfiguere x-y-z kan man alligevel starte med at en settings side hvor man kan teste ting af. Altså der er jo gratis og Open source, men f.eks. LLamaIndex har jo forskellige værtøjer afhængige af f.eks. hvor god visual /computer vision den skal have til f.eks. diagrammer og længden. 
-Almindelig UX/UI design istedet for alt er AI chat: A: hurtig fulltext søgning med forhåndsvisning af det sted hvor ordet opstår(indeksiering i PostgressSQL). B: åbne chats og data på i shadcnUI reziable komponenter hvor brugeren kan drag hvor stor vinduet skal være for de enkelte elementer. C: shortscuts til at åbne. Drag and drop mus med listen der fungere som mappestruktur med data i altså så man kan hurtig ændre hierakiet og hvor det ligger
-Man kan starte med en settingsside med konfigurationer og så videre fordi så har man også 
-Måske deep agents fra langgraph er overkill istedet for bare en simple ReAct med supabase hybrid search også en bedre model. Deep agents spawner subagents så der kan være ekstrem mange kald. Det skal helst være meget længe varende opgaver. 
-COpilotkit.ai har bugs til jeres tech stack men det er fint nok og man kan lave worksarounds. Altså med ag-ui + supabase + + copilotkit.ai. Altså hvis man vil lave generativ UI. 
-Det er fint med en stor konfiguration side og database skema men hvis brugeren reelt skal opdatere prompt + skills for at optimere det så er det bedst hvis man har en sepearat app chat/agent arkitektur som ikke laver workflows. Men så kan den fungere også med copilotkit.ai + ag-ui men så er det mere man kan få hjælp til at opdatere og ændre ting så man får bedre resultater. Altså der er jo nogle instruktuksioner på at finde/søge og analysere data. og så writer/outcome format og der er nok nogle prompts og skills til det som skal justeres i produktionen så det sidder i skabet. Så det er coolt hvis det kunne være agentic/chat baseret. Altså ligesom man som software kan ændre i sin cursor mdx, claude.md og agents.md og osv samt index.md og readme.md. 
-Fjern AI hvis strukur og data er det samme i f.eks. i meget teksttunge PDF'er uden visuelle layout.
-Funktionelle programmering + algoritmer er mere robust stadigvæk. 
-Det med at man kan attache mappe/hierakier med data til forskellige agenter/workflows er smarte og brugervenlige. Så har man en app til forskellige ting og overblik over alle data men man kan isolere data i "ø'er".
